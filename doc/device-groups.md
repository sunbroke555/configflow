# 设备组

入口：侧栏 **设备组**。设备组属于当前配置空间，同空间的 OxiDNS 和 Mihomo 共享这份草稿。

## 创建与归属

1. 新增设备组，输入 IPv4、IPv6 或 CIDR 成员，也可以从 OxiDNS 查询样本中选择客户端。
2. 选择组模式，预览生成差异、复制的拦截规则、策略路由来源变化及发布目标，再保存草稿。
3. 使用设备组页面的发布入口，先发布所有受影响的 Mihomo，再发布 OxiDNS。保存不会直接修改运行中的设备或 RouterOS。

| 模式 | OxiDNS | Mihomo |
| --- | --- | --- |
| 跟随全局 | 使用全局 DNS 规则 | 使用全局连接规则 |
| 全部直连 | 默认使用独立本地 DNS 链；可显式选择完整直连处理 | 组段以 DIRECT 结束 |
| 全部代理 | 使用代理 DNS 处理链 | 组段以所选策略组结束；只能选择启用的策略组 |

没有命中成员的 IP 归默认组。默认组可以填写显式例外成员，固定跟随全局。重叠时最长前缀优先，与组的显示顺序无关；不同组不能填写等价 CIDR。可在 **IP 归属查询** 中检查命中的成员、被覆盖的范围、基础设施排除和策略路由状态。

例如「直连设备」包含 `192.168.50.0/24`，默认组包含 `192.168.50.128/25`，直连组另有 `192.168.50.192/26`：`.50` 直连，`.150` 跟随全局，`.200` 再次归直连组。

成员不接受全地址族 `/0`、环回、fake-IP 或明确的基础设施单个地址。宽网段中的已知路由器、网关和相关 Agent 地址会从组的有效网段扣除，仍走全局处理。主机名不会在生成时解析；未核实的基础设施地址会提示核查。建议为设备设置固定 DHCP 租约。

## 仍执行 DNS 拦截

全部直连、全部代理可以开启此选项。例如需要额外过滤时，可创建「加强过滤」组。

- OxiDNS 把启用的拒绝、不存在、空应答、黑洞类 DNS 规则复制到组段开头。
- Mihomo 把启用的 REJECT、REJECT-DROP 连接规则复制到组段开头。
- 两者均在全局第一个启用的 MATCH 处截止，不复制 MATCH 本身，也不复制其后的规则。
- 组内拦截优先：原全局表中位于拦截之前的普通允许规则不会成为组内豁免。预览会列出复制项及截止后排除项。
- 完整参数（native）模式无法可靠提取 DNS 拦截，必须关闭此选项；保存、导入和切换模式均会检查。

自定义处理链不能在直连、代理和全局处理之间共用缓存实例或缓存文件。完整直连使用的本地缓存，也不能被自定义主表行重复调用；发现这种形态时会拒绝保存或生成，并提示改用独立缓存。

这个开关不控制 hosts 和 AdGuard，它们仍按现有全局前缀执行。设备组不提供整组禁止联网功能。

## 升级旧设备策略

有旧 OxiDNS 设备策略的空间必须点击 **升级为设备组**。打开页面或读取配置不会自动迁移。

升级预览列出将创建的组、策略路由来源、两种引擎的生成差异、基础设施样本及需重新发布的 Agent。迁移执行前会再次检查配置版本和 Agent 绑定。

- direct 成员迁入「直连设备」，保持默认的独立直连 DNS，不自动开启拦截。
- smart 成员初始化独立的策略路由 include；位于 direct 范围内的 smart 例外加入默认组。
- 「直连设备」加入来源的 exclude_groups；不创建智能分流组。
- 在同一保存事务中清空 `oxidns.device_policies` 和模板镜像中的旧策略。
- RouterOS 的来源列表按条目与顺序保持一致；升级保存不会改写路由器已发布状态。
- 已启用的 RouterOS 规则自动同步会因来源控制模型改变而暂停。手动预览、发布一次路由器策略即可刷新同步基线；来源未变时对路由器生成零条来源变更，运行中的来源与流量不受保存操作影响。
- Mihomo 新增连接层的组段，因此 direct 成员的连接行为会发生变化；只对实际进入 Mihomo 的连接生效。

旧成员不符合新模型，或原生配置的受管链被手动修改时，预览会阻断并说明原因，保留旧配置。升级后旧设备策略接口仍可读取只读摘要，写入返回冲突并引导到设备组页面。

## 策略路由来源与发布

路由器策略页独立编辑「包含来源」和「排除设备组」。排除按设备组归属计算，包括默认组的补集语义。设备组的 DNS 模式不再决定 RouterOS 来源；未升级的空间仍沿用旧推导。

调整成员、排除组或删除来源时，如果设备将离开策略路由，保存预览会提示移除范围。RouterOS 仍需单独预览、发布。来源策略目前只处理 IPv4。

设备组发布固定配置快照和目标列表。任一 Mihomo 离线、版本未知、失败或待激活时暂停后续 OxiDNS。重试先查询原发布任务，未知状态不会直接换任务重发。配置、绑定或连接信息变化后，需要重新预览；刷新页面可恢复批次状态。设备组发布期间，相应 DNS 联动等待批次结束。

Mihomo 至少需要 1.19.1 才支持这里使用的 inline 来源匹配组合；其他规则功能可能要求更新版本。实际 Agent 发布前读取内核版本。订阅与下载提示最低要求，但不能核验接收方。

## 客户端 IP 与当前限制

设备组依据服务看到的来源 IP 匹配。DNS 经路由器转发、DNS guard hairpin 或 NAT 改写后，OxiDNS/Mihomo 可能只看到基础设施地址。优先通过 DHCP 让客户端直接查询 OxiDNS，并使用页面的客户端样本和手动诊断核查。

样本是多台 OxiDNS 的有界查询记录汇总，不是设备清单，也不是去重后的请求总量。无记录、Agent 离线、版本过旧与查询记录关闭分别显示，不能据此断言设备组未生效。基础设施样本占比只在有有效样本时显示。

RouterOS 来源保留诊断读取实际 NAT 规则，并按组网段和目的路径检查。同一网关 `/24` 的保护不能证明跨网段安全。选择性网关只接管特定目标；直接访问 IP 或未接管的连接可能不经过 Mihomo。完整 TUN 应按实际接管范围核查。

IPv6 隐私地址可能轮换，DNS 与连接路径需要分别确认。已有连接和 DNS 缓存不会随换组立即消失，可能需要等待 TTL 或重新联网。跟随全局仍共享动态分类和 fake-IP 池。

MosDNS、Surge、Loon 暂不生成设备组，配置内容保持原有全局规则，并在预览和下载响应中警告。第一步不支持逐条规则的适用设备、组私有 DNS 上游、按组跳过 hosts/AdGuard 或网关安装向导联动。
