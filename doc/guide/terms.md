# 常见名词，用日常话解释

[文档首页](../README.md)

不需要背这些名词。看到界面上不认识的词时，再回来查。

## 程序与设备

| 界面中的名称 | 可以怎样理解 |
| --- | --- |
| ConfigFlow / 管理面板 | 用浏览器打开的管理台，负责整理设置、生成文件和管理设备 |
| 核心 / Mihomo / OxiDNS / MosDNS | 真正干活的程序。Mihomo 处理网络连接；OxiDNS、MosDNS 处理“网站名称对应哪个地址”的查询 |
| Agent | 被管理设备上的小助手，接收面板的操作、写配置并报告状态；它不是代理节点 |
| 客户端设备 | 家里的手机、电脑、电视等实际使用网络的设备 |
| 主路由 / 上游路由 | 通常是负责全家上网、分配地址的那台路由器 |
| 网关 | 设备把需要转交的网络数据送往的下一站。改设备的网关可能改变它的上网路径 |
| Shell 安装 | 在 Linux 设备的命令行里粘贴并运行安装命令，程序直接装在设备上 |
| Docker / 容器 | 把程序及运行环境打包起来运行的方式；NAS 的容器管理工具通常也使用它 |
| Host 网络 | 容器直接使用宿主机的网络，端口也与宿主机共用 |
| Bridge 网络 | 容器在单独的内部网络里，需要“宿主机端口 → 容器端口”的映射才能从外部访问 |
| Macvlan 网络 | 给容器分配一个单独的局域网地址；需要确认路由器、交换机和宿主机支持这种用法 |

## 配置与规则

| 界面中的名称 | 可以怎样理解 |
| --- | --- |
| 节点 | 一个可用的代理出口，通常由订阅提供，也可手动添加 |
| 订阅 | 一个能下载节点列表的地址，更新后列表可能改变 |
| 订阅聚合 | 把多个已有来源重新组合成一个来源，便于反复使用 |
| 策略组 | 一篮子候选出口，以及“由谁决定选哪个”的办法，例如手动选、挑速度更好的或坏了就换 |
| 策略规则 | 一条“遇到什么情况，就怎么处理”的安排，例如某网站直连、某类连接走某个组 |
| 规则集 | 事先整理好的一整份网站或地址清单，引用它就不必逐条手填 |
| 直连 / DIRECT | 不经过代理节点，使用设备原有的网络访问 |
| 拒绝 / REJECT | 阻止符合条件的连接或查询 |
| 配置空间 | 一份独立方案，如“家庭”“办公室”。方案有自己的规则和设置，但共用订阅、节点和规则库 |
| 草稿 | 已在面板保存、但不一定已经发送到设备的配置 |
| 发布 / 推送 | 把面板中的配置交给指定设备应用；应继续查看发布步骤与检查结果 |
| YAML / 配置原文 | 程序能读懂的文本设置文件，空格和缩进也有意义。没有把握时先备份，优先用可视化输入框 |
| 正则表达式 | 一种按文字规律筛选名称的写法。普通用户可先只填明确的名字或关键词，复杂写法先预览 |

## 网站名称查询与双机备用

| 界面中的名称 | 可以怎样理解 |
| --- | --- |
| 域名 | 网站名称，例如 `example.com` |
| IP 地址 | 设备在网络上的地址，常见形式如 `192.168.10.20`；IPv6 地址含冒号 |
| DNS | 把网站名称查成可访问地址的服务 |
| DNS 上游 | 本地程序自己回答不了时，继续向谁查询 |
| DoH / DoT | 通过加密连接进行网站名称查询；服务地址必须按对方要求填写 |
| 缓存 | 暂时保存已经查到的结果，重复查询时更快；清空后需要重新查 |
| Fake-IP | 程序先给出一个内部使用的临时地址，再把后续连接送到正确位置。必须与流量接管方案配套 |
| TUN | 程序用来接收设备网络连接的一种虚拟入口。勾选它不代表主路由或其他设备已经改好 |
| IPv4 转发 | 允许这台 Linux 设备把收到的数据转交给其他设备。打开这个能力，与完成整套分流规则不是同一回事 |
| 高可用 / 主备 | 准备两台设备，一台工作，另一台在前者故障时接替 |
| VIP / 共同服务地址 | 两台主备轮流使用的一个局域网地址，客户端一直使用这个地址，不必随主备切换修改 DNS |
| VRID | 同一局域网里一组主备的编号，避免与另一组混淆；它不是端口 |
| 预检 | 启用前检查必要条件。通过预检不等于已经验证断网接替成功 |
