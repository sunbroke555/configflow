# 规则库：保存可重复使用的域名或 IP 名单

本页目录：[先做一次](#先做一次) · [添加规则集](#添加规则集) · [给内容型规则集追加规则](#给内容型规则集追加规则) · [加入当前配置](#加入当前配置) · [列表和批量操作](#列表和批量操作) · [生效与常见问题](#生效与常见问题)

入口：**共享资源 → 规则库**。这里存“哪些域名或 IP 属于同一类”的名单。把名单加入 [策略规则](rules.md)，再决定它们走直连还是代理。

规则库由所有配置空间共用。修改某个名单的地址、内容、类型或启用状态，会影响所有引用它的配置；只想改一个配置的去向，应改那个配置里的「策略」，不要改共享名单。

## 先做一次

1. 点「添加规则集」，名称填“公司内网”。
2. 来源类型选「规则内容」，类型选 `Domain`，内容格式选 `Text`。
3. 每行填一条域名，例如 `+.corp.example` 表示该域名及其子域名。只匹配一个主机时使用完整域名，如 `intranet.example`。
4. 保持启用并保存，点「加入当前配置」，选择所需目标策略。
5. 如果使用 OxiDNS，在同一窗口选择 DNS 去向；公司内网通常需要指定能够解析它的内网 DNS。保存后仍需生成并发布。

远程规则集则选择「规则地址」，填可信来源的完整下载 URL，并按来源真实内容选择类型和格式。

## 添加规则集

| 选项 | 怎样选择；结果 |
| --- | --- |
| 规则名 | 取能说明用途的名称，例如“公司内网”“广告域名”。这是共享来源的名字，不是流量策略。 |
| 来源类型：规则地址 | 由远程 HTTP(S) 地址提供名单；适合有人维护、需要更新的规则。你改的是来源声明，不会把修改写回远端网站。 |
| 来源类型：规则内容 | 直接保存你粘贴的名单，适合少量自定义域名或 IP。更新由你自己维护。 |
| 规则地址 | 填实际文件地址，避免填仓库网页的 HTML 页面。若下载受限，检查系统「规则下载代理」或下文「GitHub 代理」。 |
| 规则内容 | Text 每行一条；YAML 使用 `payload:` 列表。字段类型必须与内容一致，错误行按校验提示处理。 |
| 类型：Domain | 只装域名匹配内容，适合域名分流与 DNS 分流；不要混入 `IP-CIDR,` 行。 |
| 类型：IP CIDR | 只装 IPv4/IPv6 网段，例如 `192.0.2.0/24`。用于连接分流；OxiDNS 标准域名分流不会用这类名单判断查询去向。 |
| 类型：Classical | 混合带规则类型的行，例如 `DOMAIN-SUFFIX,example.com`、`IP-CIDR,192.0.2.0/24`。规则行不必附加本配置的最终策略，目标策略在引用时选。支持程度还取决于生成的软件。 |
| 内容格式：自动识别 | 先按界面识别；远程地址主要依据后缀，链接后缀与内容不一致时应手动指定。 |
| Text · 每行一条 | 简单文本名单。不要把 YAML 的 `payload:` 也作为普通规则行粘进去。 |
| YAML · payload 列表 | 内容包含 `payload:` 和缩进列表时选它；缩进和引号必须合法。 |
| MRS · 二进制规则 | 仅远程地址可选，适用于来源确实提供的 Mihomo 二进制规则。不能把普通文本改个格式标签就变成 MRS；需要其他目标转换时，应先确认该类型被支持。 |
| 启用／停用 | 启用后可正常引用；停用会阻止所有引用配置正常采用这个来源。临时排查可停用，但要核对它原本承担的直连、代理或拒绝规则。 |
| 保存／取消 | 保存共享来源或放弃未保存的表单。内容校验失败时先修正，不要把按钮点击当成已保存。 |

## 给内容型规则集追加规则

只有可以直接编辑的内容型来源提供「添加规则」。远程来源应在上游修改，或另外建立一个自己的内容型规则集。

| 选项 | 用法 |
| --- | --- |
| 匹配范围：仅此域名 | 只匹配输入的域名，不自动包含子域名。适合只改一个服务。 |
| 此域名及其子域名 | 同时匹配父域名及其下级。适合整家公司或网站，范围比上一项大。 |
| 按输入内容（含通配符） | 原样按输入规则表达匹配范围；已经知道通配符写法时使用，不确定先选前两项。 |
| 规则类型 | Classical 名单中选择具体类型；IP 名单按网段填写，不能混成域名行。 |
| 值 | 可逐行输入多个值；检查最终预览是否与预期一致。 |
| 将写入的内容 | 展示会添加的实际规则行。保存前核对，尤其是父域名范围和 IPv6 网段。 |
| 添加／取消 | 添加会改变共享名单，影响所有引用它的配置；取消只放弃当前输入。 |

在「策略规则」里展开并编辑来源内容，同样是在修改这份共享名单；进入的页面不同并不会改变影响范围。其他页面已更新同一规则集时，版本检查会拒绝覆盖，重新读取后再编辑。

## 加入当前配置

在规则集行点击「加入当前配置」，或勾选多项后批量加入。

| 选项 | 推荐与结果 |
| --- | --- |
| 目标策略 | 选 `DIRECT` 让连接直连，或选已建好的代理策略组。拒绝类策略只控制连接，不等于自动屏蔽 DNS 查询。 |
| DNS（OxiDNS） | 独立决定如何查询域名；常规用「跟随策略」，公司内网可选「指定上游」。详见 [策略规则 DNS 表](rules.md#dnsoxidns-怎么选)。 |
| 加入配置 | 只给顶部当前配置添加引用。已经引用过的项目不会无意义重复添加；停用来源应先启用。 |

加入后去「策略规则」检查顺序。前面的规则先匹配，不能仅靠名单名字判断优先级。

## 列表和批量操作

| 操作 | 会做什么 |
| --- | --- |
| 搜索、类型筛选、卡片／列表 | 改变列表显示；不改内容、不发布。 |
| 全选、单项复选框 | 决定「加入当前配置」「批量下载内容」「删除 N 项」的操作范围，执行前确认已选数量。 |
| 复制下载地址 | 复制 ConfigFlow 提供的规则地址，可能包含访问令牌；分享前检查权限含义。不是规则集备份。 |
| 批量下载内容 | 将选中规则下载/保存为服务器可用内容；这是更新面板缓存，不是下载 ZIP 到浏览器。失败保留上次有效缓存，界面区分“保留了旧缓存”与“无可用缓存”。 |
| 更多 → 批量测试连通性 | **测试全部 URL 型来源，失败的来源会被自动停用。** 不是只测试已勾选项，也不是纯只读诊断；内容型来源跳过。临时网络故障也可能造成停用，测试后应检查状态并按需重新启用。 |
| 更多 → 批量导入 | 粘贴 YAML `rule-providers` 声明批量建立来源，不是粘贴任意整份客户端配置。导入后看成功项和失败项，修正剩余项再试。 |
| 更多 → GitHub 代理 | 设置 GitHub 下载备用镜像前缀。面板会先尝试原始地址，失败后使用备用；生成配置中的 GitHub 链接也受影响。它与系统的 HTTP/HTTPS「规则下载代理」是两类设置。 |
| 更多 → 调整顺序 | 调整规则库展示顺序并保存；不会替你重排各配置空间里已经引用的策略规则。 |
| 编辑 | 改共享来源的完整声明；改 URL、格式或类型后需重新核对下载内容。 |
| 删除／删除 N 项 | 仍被配置使用时需先解除引用。批量删除要读结果，不能假定所有项目都成功。 |

「批量测试连通性」目前使用服务器发出的 HTTP HEAD 检查。某些站点拒绝 HEAD，即使普通下载可用也可能被判失败；检查错误和实际下载结果后再决定是否保留该来源。

## 生效与常见问题

保存名单后，后续生成会读取新来源；已经运行的设备需要规则更新或重新发布。DNS 去向、客户端连接策略与规则文件内容是不同层次，修改其中一个不能保证其他两个同时变化。

- **内容看似正确却报格式错误：**核对 Domain / IP CIDR / Classical 和 Text / YAML 是否匹配，尤其是远程文件的真实内容。
- **选了规则集却没有分流：**确认已加入当前配置、已启用、顺序在兜底前，并已发布到正确设备。
- **改一个配置却影响多个设备：**你可能编辑了共享来源；仅改变单个配置去向时，到该配置的「策略规则」修改引用。
- **网络恢复但规则仍停用：**批量连通性测试可能停用了它；恢复网络后需要核对并重新启用。
