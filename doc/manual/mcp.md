# 用 AI 客户端管理 ConfigFlow

[文档首页](../README.md) · [系统设置](system-settings.md)

MCP 是让 AI 客户端连接其他软件的一种方式。接入后，你可以让 AI 读取 ConfigFlow 的状态、帮你整理规则或修改配置，不必每次自己在网页里逐项操作。

**只有希望通过 AI 管理 ConfigFlow 时才需要设置。** 日常添加订阅、生成配置、管理设备都可以继续在网页完成。MCP 已包含在 ConfigFlow 中，不需要再装一个服务，也不需要另外设置端口。

## 先准备地址和访问令牌

1. 打开 **系统 → 系统设置 → 常规 → 服务配置**。
2. 核对 **服务域名**。这里也可以填完整 IP 地址，例如 `http://192.168.1.10:5010`；必须是 AI 客户端能够访问的地址。改好后点到输入框外，等待保存成功。
3. 找到 **访问令牌**。已有令牌时沿用；首次设置时，点击旁边的 **生成随机令牌**，出现“令牌已生成并保存”后复制输入框中的内容。
4. 在下方 **MCP** 一行点击 **复制 MCP 地址**。复制的地址类似 `http://192.168.1.10:5010/mcp`。

**复制 MCP 地址只复制地址，不会把令牌一起带上。** 你还需要按下一节填写认证信息。不要把网页登录账号、密码当作访问令牌。

同一台电脑上的浏览器能打开面板，不一定表示 AI 客户端也能访问。如果客户端运行在另一台机器，要用面板的实际地址；如果连接请求由云端发出，云端通常不能直接访问 `192.168…` 这样的家用局域网地址，需先确认该客户端支持怎样连接你的服务。

## 在 AI 客户端里怎么填

不同客户端的菜单名称不一样，找到它的“MCP”“工具连接”或“添加服务器”功能，按下面的通用字段填写。需要支持 **HTTP / Streamable HTTP** 方式；只支持本地命令或旧式 SSE 的入口不能直接套用。

| 客户端中的字段 | 填写内容 | 注意什么 |
| --- | --- | --- |
| 名称 | 例如 `ConfigFlow` | 只是方便你辨认，可以自定义 |
| 连接方式 / 类型 | `HTTP` 或 `Streamable HTTP` | 不选 SSE，也不需要填写运行命令 |
| URL / 服务地址 | 从系统设置复制的完整 MCP 地址 | 保留末尾 `/mcp`；不用改成 `/api` 或网页登录地址 |
| 认证方式 | 如果有此选项，选择 `Bearer Token` | 使用系统设置里的访问令牌 |
| Token / Bearer Token | 只粘贴令牌本身 | 此类输入框通常会自行加认证格式，按客户端的字段说明填写 |
| Headers / 请求头 | 名称填 `Authorization`，值填 `Bearer 你的访问令牌` | 客户端没有单独令牌框、但允许自定义请求头时使用；`Bearer` 后有一个空格 |

单独令牌框和自定义请求头是两种填写方式，按客户端实际提供的入口选一种即可。填写后使用客户端的保存、连接或重新连接功能，等待它读取可用工具。

### 客户端只能填写 URL 时

如果客户端支持 HTTP MCP，但不能填写认证请求头，可把令牌放在地址后面：

```text
http://192.168.1.10:5010/mcp?token=你的访问令牌
```

把示例 IP、端口和令牌换成自己的值。这时**整条地址都含有管理凭证**，应像密码一样保管。自己设置的令牌若含特殊字符，需要按客户端要求进行网址编码；不熟悉时使用系统生成的随机令牌更方便。

## 第一次连接，先只读取

在 AI 客户端中，可以先这样说：

> 连接 ConfigFlow，读取概览和配置空间列表，告诉我有哪些配置空间、哪个是默认空间。先不要修改配置或向设备发布。

看到自己的配置空间和状态，才说明连接和认证已基本成功。不要用“重置配置”或“重启设备”测试是否连通。

若客户端能显示工具列表，可以先使用 `get_overview` 或 `list_profiles`；这两个名称分别对应“读取概览”和“列出配置空间”。普通使用不需要自己编写请求内容。

## AI 可以帮你做什么

| 你希望做的事 | 可以怎样交代 AI | 操作会影响哪里 |
| --- | --- | --- |
| 查看状态和查错 | 列出离线 Agent，查看指定设备或面板最近的错误 | 读取状态和日志，不必修改配置 |
| 整理订阅、节点和聚合 | 查看现有来源，再按你的要求添加、修改、删除或更新 | 这些资源由所有配置空间共用 |
| 调整策略组和规则 | 指定配置空间，先说明改动，再保存 | 修改该空间的配置；需要另外确认是否发布到设备 |
| 检查分流规则 | 检查某个网站会命中什么规则，找重复规则 | 用于检查；不要把所有名为“测试”的工具都理解为只读操作 |
| 修改 DNS 设置 | 指定空间及 MosDNS 或 OxiDNS，说明要改什么 | 保存对应空间的设置，实际设备仍需按发布结果确认 |
| 预览和生成配置 | 先预览，再按需要生成 | 当前 MCP 支持 Mihomo、Surge、MosDNS、OxiDNS；Loon 请使用网页 |
| 管理 Agent | 查看日志、状态，或按明确指令推送配置、重启、更新、卸载 | 会涉及实际设备；先核对设备名字、地址和绑定空间 |
| 系统设置与备份 | 读取设置、安排备份，或在明确范围内恢复配置 | 系统操作可能影响全部空间，不只影响正在查看的一个 |

页面里有某个功能，不代表 MCP 一定提供相同操作。以客户端实际读取到的工具为准；找不到时继续用对应网页，不必让 AI 猜工具名称。

规则库的批量连通性测试会自动关闭失败来源，可能影响所有空间。要检查这类操作，先让 AI 说明将调用哪项功能、是否会改设置。更多说明见 [规则库](rule-library.md)。

## 一定要说清楚配置空间

网页顶部选中的空间，**不会自动传给 AI 客户端**。让 AI 修改策略组、规则或 DNS 设置前，先让它列出空间并确认目标 ID。

例如可以说：

> 这次只处理“家庭”空间，ID 是 `home`。先检查当前规则并说明准备改哪些内容，确认后再保存；暂时不要推送到 Agent。

支持按空间操作的工具使用 `profile_id` 指定目标。不指定时使用系统设定的**默认配置空间**，而不是浏览器当前选中的空间，也不能假定默认 ID 永远叫 `default`。

还要注意以下范围：

- **订阅、节点、聚合、规则库、系统设置和全量备份**属于共享或全局操作。即使指定 `profile_id`，也不会把这些操作缩小成只影响一个空间。
- **Agent 推送**按该设备自己的绑定空间取配置。推送前要核对 [Agent](agents.md) 的绑定，不能只看 AI 上一次操作了哪个空间。
- 恢复全部数据、重置系统和卸载 Agent 都是可用的管理能力，不是只读查询。需要这类操作时，先明确对象和范围，并从 [系统设置](system-settings.md#备份与升级) 保留恢复用备份。

## 保存、生成和发布有什么区别

**预览**用于查看准备生成的内容；**保存设置**先更新面板里的配置；**向 Agent 发布**才进入设备应用流程。让 AI 报告“已保存”，不等于设备已使用新配置。

Mihomo、Surge 的生成操作会保存生成文件；MosDNS、OxiDNS 的打包结果需要在网页下载。AI 返回生成成功摘要，不等于文件已经下载到你的电脑。完整操作见 [配置生成](generate.md)。

推送后，到 Agent 页面检查发布记录和设备状态。看到“待应用”“失败”或“结果未确认”时，不能按发布成功处理；不要只看 AI 是否回复“请求已提交”。

AI 返回的配置内容会隐藏部分内部凭据，不能代替完整恢复备份。准备迁移或做较大修改时，仍在系统设置点击 **导出全部数据** 并保存文件。

## 令牌怎么保管、更换和停用

当前访问令牌与配置下载链接共用，**持有它就能调用 MCP 管理操作**，不只是下载订阅。系统设置没有单独的 MCP 专用令牌，也没有仅供查询的令牌选项。只把它配置到自己信任的客户端，不要公开分享含令牌的链接或截图。

| 操作 | 怎么做 | 后续要处理什么 |
| --- | --- | --- |
| 保留当前令牌 | 不点击生成或清除，沿用已有值 | 已连接的客户端继续使用原值 |
| 生成新令牌 | 点击 **生成随机令牌**，等待保存成功 | 旧令牌失效；更新 MCP 客户端的认证信息，以及仍使用旧令牌的配置下载链接 |
| 自己填写新令牌 | 输入非空内容，再点到输入框外，等待保存成功 | 同样需要更新使用旧令牌的客户端；不用重启面板 |
| 清除令牌 | 点击 **清除令牌** 并确认 | 取消此令牌保护；只把输入框删空不会保存清除操作 |
| 不再让某个 AI 客户端连接 | 在那个客户端中移除 ConfigFlow 连接 | 不影响网页日常使用；若令牌已经泄露，再更换令牌并更新其他客户端 |

**清除令牌不是关闭 MCP。** 如果同时没有启用网页登录，清除后 MCP 将不再要求凭证；已启用网页登录时，仍可使用有效的登录凭证认证。日常接入建议保留访问令牌，不要为了排查连接而清空它。

## 连不上时按什么顺序查

| 现象 | 先检查什么 |
| --- | --- |
| 超时、无法访问 | 面板是否运行、地址与端口是否正确，以及真正发起 MCP 连接的设备能否访问该地址 |
| 返回 404 | 地址末尾是否为 `/mcp`；通过其他服务器转发访问时，确认它也转发这个路径 |
| 返回 401 / 未授权 | 令牌是否复制完整、是否刚更换；请求头是否为 `Authorization: Bearer 令牌`；不要填网页登录密码 |
| 返回 405，或一直等待 SSE | 使用 HTTP / Streamable HTTP 方式。直接在浏览器打开 `/mcp` 也可能显示 405，这不表示整个服务坏了 |
| 以前能连，后来认证失败 | 核对访问令牌是否改变；如果使用的是临时登录凭证，它可能已经过期，建议改为系统设置中的访问令牌 |
| 找不到工具，或提示不支持某个目标 | 刷新客户端的工具列表；确认当前功能受支持。Loon 的预览和生成使用网页 |
| 已连上，但某次操作提示失败 | 阅读返回的具体原因；检查资源引用、所选空间或目标设备状态，不要反复重试删除、重置或推送 |
| 改到了另一套配置 | 核对传给工具的 `profile_id`、系统默认空间及 Agent 绑定，网页顶部选择不会替你限制 MCP |

仍无法定位时，记下发生时间和客户端显示的完整错误，再到 [日志](logs.md) 查同一时间的记录。分享排错信息前遮住令牌、订阅地址和密码。
