# Mihomo IPv6 检查与准备

适用于客户端继续以 IPv4 分流为主，同时让 Mihomo 使用 IPv6 节点的环境。客户端 IPv6 Fake-IP 是另一个需要路由配套的环节，检查结果会单独列出。

## 使用流程

1. 在生成页的「Mihomo 基础配置」或 Mihomo 面板的设置中，分别设置「Mihomo 使用 IPv6」和「DNS 返回 IPv6 地址」。两个开关直接编辑同一份 YAML；手写配置会同步显示。空配置首次操作开关时使用实际默认模板，保留默认 DNS 等设置。
2. 保存草稿，展开「设备 IPv6 检查」。从设备面板进入时固定检查该设备；从生成页进入时选择本配置空间的 Mihomo 设备。检查是只读的。
3. 查看已保存草稿、设备上的配置、主机地址与默认路由、转发与 RA、开机恢复配置、实际 TUN，以及关联 RouterOS 的检查结果。通过 RA 学到并有有效期的默认路由是正常状态。
4. 点击「补齐缺少的配置」。操作前会重新核对配置、设备绑定和路由状态；有冲突或检查结果过期时停止。仅为已关联上游路由或启用 Linux 网关的设备自动开启转发。
5. 通过「保存并发布」把 YAML 应用到 Mihomo。保存草稿和网络准备不会代替配置发布；草稿与设备配置不同会单独提示。
6. 再次检查，并点击「验证 IPv6 连接」。该检查验证配置空间中可识别 TCP 节点的 IPv6 端口，绑定实际上联网卡，防止 TUN 提前接收连接而误报。它不代表代理协议握手或全部客户端流量已经通过。订阅远程节点、链式代理与 UDP 节点需在 Mihomo 面板另行验证。

## 自动修改的范围

- Linux Shell Mihomo Agent `1.8.50-go` 起支持。Docker 等不支持自动主机配置的环境保留只读说明。
- 检查实际上联网卡，补齐 IPv6 转发；依赖 RA 时，补齐该网卡的 `accept_ra=2` 和默认网关学习。已有静态默认路由不被改成 RA。
- 已有正确的用户 sysctl 配置保持原样，并显示文件及行号。仅缺失参数写入 `/etc/sysctl.d/99-configflow-ipv6.conf`，管理记录位于 Agent 配置目录的 `ipv6-readiness.json`。有后加载冲突、文件被外部修改或网卡身份变化时停止覆盖。
- 明确执行过准备后，Agent 开机恢复受管参数。启用 IPv6 Fake-IP 时，如果 Mihomo 早于主机 IPv6 就绪启动而缺少 IPv6 TUN 地址，会在地址和路由就绪后，对仍在运行且本地控制接口匹配的 Mihomo 热重载一次。不会启动已经停止的核心；等待超时、接口认证失败或配置不匹配会保留现状并给出检查提示。
- RouterOS 自动操作仅添加缺失且下一跳唯一的 IPv6 Fake-IP 路由。优先使用同 LAN 的稳定 ULA，或带 RouterOS 接口范围的链路本地地址。已有正确路由沿用，错误、停用、冲突路由保留并提示。新增失败会核对归属后撤销本次路由。
- DNS、DHCPv6 `use-peer-dns`、RA 广播 DNS、NAT66、防火墙、MSS 和自动回流只检查或提示，不作为 IPv6 开关的固定修改项。保持现有 IPv4 分流。

## 结果的含义

「配置开启」「发现持久化文件」「节点端口可达」「实际重启恢复」是不同证据。页面不会把文件存在当作用户设备已通过重启测试，也不会把节点端口可达当作完整代理连接成功。

关闭 YAML 中的 IPv6 开关不会删除已有系统网络参数或路由。外部网络、运营商前缀分配、多默认路由和无法确认的防火墙策略需要单独处理；自动准备不会猜测或重建这些配置。
