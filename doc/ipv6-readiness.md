# Mihomo IPv6 检查与准备

适用于客户端继续以 IPv4 分流为主，同时让 Mihomo 使用 IPv6 节点的环境。客户端 IPv6 Fake-IP 是另一个需要路由配套的环节，检查结果会单独列出。

「Mihomo 使用 IPv6」允许 Mihomo 连接 IPv6 节点或网站，设备本身也要有可用的 IPv6 网络。「DNS 返回 IPv6 地址」决定 Mihomo DNS 是否给手机、电脑返回 IPv6 地址；客户端继续走 IPv4 分流时可以关闭，不影响 Mihomo 使用 IPv6 节点。

如果希望客户端也通过 IPv6 访问，还要准备好对应的 IPv6 路由。搭配 OxiDNS 时，应检查「优先 IPv4」等设置是否压下 IPv6 答案；只打开 Mihomo 的 DNS 开关不会自动修改 OxiDNS 或路由器设置。

## 使用流程

1. 在生成页的「Mihomo 基础配置」或 Mihomo 面板的设置中，分别设置「Mihomo 使用 IPv6」和「DNS 返回 IPv6 地址」。两个开关直接编辑同一份 YAML；手写配置会同步显示。空配置首次操作开关时使用实际默认模板，保留默认 DNS 等设置。
2. 保存草稿，点击 IPv6 开关旁的「检查设备」，打开独立检查窗口。从设备面板进入时固定检查该设备；从生成页进入时选择本配置空间的 Mihomo 设备。检查是只读的，关闭窗口后保留 YAML 草稿。
3. 查看已保存草稿、设备上的配置、主机地址与默认路由、转发与 RA、开机恢复配置、实际 TUN，以及关联 RouterOS 的检查结果。通过 RA 学到并有有效期的默认路由是正常状态。
4. 点击「补齐缺少的配置」。操作前会重新核对配置、设备绑定和路由状态；有冲突或检查结果过期时停止。仅为已关联上游路由或启用 Linux 网关的设备自动开启转发。
5. 通过「保存并发布」把 YAML 应用到 Mihomo。确认这次发布成功后，后台自动验收该设备和这次发布的配置版本。保存草稿、网络补齐、待激活或失败的发布都不会被当作发布成功。
6. 查看发布栏中的验收摘要，展开可看各项结果。也可在设备检查窗口点击「验证连接与分流」，按当前已保存版本重新验证。结果分别显示配置与主机网络、实际 DNS 应答、代理网站访问、IPv6 传输和客户端路径；未取得证据的项目显示未验证。

## 验收设置

默认执行 Mihomo 主机自检。在设备检查窗口底部展开「验收设置」，可以选择独立检测客户端和检测网址。

- 不配置客户端时，检查主机、DNS 和代理访问；客户端整条路径单独显示「未验证」。主机自检通过不代表手机、电脑的流量已测过。
- 检测客户端必须是本配置空间中独立的在线 Linux Agent，需要位于 ROS 后面，并使用平时的 DNS 和默认网关。Mihomo 主机自身不作为独立客户端。界面不会自动选择；原设备离线、改绑或不支持检测时，需明确重新选择或改为仅检查主机。
- 检测网址留空时按运行配置选择。自定义地址只接受不含账号密码的 HTTP 或 HTTPS 网址。
- 保存设置后，后续手动验证和发布后验收使用这些设置。配置客户端后会检查它的 DNS、实际访问及对应的 Mihomo 连接证据；缺少任何必要证据时保留未验证或提醒，不把主机结果代替客户端结果。

验收在后台执行，可以关闭检查窗口或离开页面。结果会保存，重新打开设备检查可读取；发布栏的自动结果始终对应那次发布，不会把之后编辑的草稿算进来。设备、配置版本或验收设置已变化时，旧结果不能用于证明当前状态。

## 自动修改的范围

- Linux Shell Mihomo Agent `1.8.50-go` 起支持。Docker 等不支持自动主机配置的环境保留只读说明。
- 检查实际上联网卡，补齐 IPv6 转发；依赖 RA 时，补齐该网卡的 `accept_ra=2` 和默认网关学习。已有静态默认路由不被改成 RA。
- 已有正确的用户 sysctl 配置保持原样，并显示文件及行号。仅缺失参数写入 `/etc/sysctl.d/99-configflow-ipv6.conf`，管理记录位于 Agent 配置目录的 `ipv6-readiness.json`。有后加载冲突、文件被外部修改或网卡身份变化时停止覆盖。
- 明确执行过准备后，Agent 开机恢复受管参数。启用 IPv6 Fake-IP 时，如果 Mihomo 早于主机 IPv6 就绪启动而缺少 IPv6 TUN 地址，会在地址和路由就绪后，对仍在运行且本地控制接口匹配的 Mihomo 热重载一次。不会启动已经停止的核心；等待超时、接口认证失败或配置不匹配会保留现状并给出检查提示。
- RouterOS 自动操作仅添加缺失且下一跳唯一的 IPv6 Fake-IP 路由。优先使用同 LAN 的稳定 ULA，或带 RouterOS 接口范围的链路本地地址。已有正确路由沿用，错误、停用、冲突路由保留并提示。新增失败会核对归属后撤销本次路由。
- DNS、DHCPv6 `use-peer-dns`、RA 广播 DNS、NAT66、防火墙、MSS 和自动回流只检查或提示，不作为 IPv6 开关的固定修改项。保持现有 IPv4 分流。

## 结果的含义

「配置开启」「发现持久化文件」「代理网站访问」「使用 IPv6 连接节点」「客户端全链路」「实际重启恢复」是不同证据。页面按检查范围显示结果，只有该范围所需项目都有通过证据时才显示通过。找到持久化文件不代表用户设备已经实测重启；网站访问成功也不能单独证明使用了 IPv6 节点或客户端路径正常。

关闭 YAML 中的 IPv6 开关不会删除已有系统网络参数或路由。外部网络、运营商前缀分配、多默认路由和无法确认的防火墙策略需要单独处理；自动准备不会猜测或重建这些配置。
